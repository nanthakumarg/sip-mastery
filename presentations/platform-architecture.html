01 overview / what it is

The SIP edge executes. The backend decides.

Every decision (who may register, who may call, where the call goes, how long it may last) is made by the billing backend, reached through a sidecar on each Kamailio node.

What the platform does
  • Registration with digest auth verified by the backend; contacts in a shared MySQL location table.
  • Calls from trusted origination gateways (IP, port, transport) and from registered subscribers.
  • Routing: R-URI rewrite, local subscriber first, otherwise termination gateways with serial failover.
  • Prepaid control: money reserved before time is granted; re-authorization; disconnect at the exact second.
  • Records: Start, Final and Failed IPDRs, from which the backend builds CDRs and settles the ledger.
  • Media: RTPEngine anchoring, media timeout, per-call recording.
  • Admin: React UI for tariffs, routing, gateways, balances, reports, live calls and disconnect.
Rules the whole design follows
Fail closedNo decision, no registration or call. No call outlives its allowance.
2sidecar round trips per accepted call: call.identify, call.setup
0 sgrace period: the call ends at T unless a grant arrived first
≥ 1×IPDR delivery: spooled to disk, deduplicated on event ID

Out of scope: ProSBC, WebRTC / SRTP, transcoding, digests other than MD5.
Deferred: push-and-wait, PSTN fallback, emergency numbers, channel limits, payment gateway.

01 overview / trust boundaries

Three trust zones; no secret crosses into the SIP tier

The SIP tier never holds a password or an HA1. Each node proves who it is to the backend with its own certificate.

Public edge trusts nothing
  • Strips any X-Src-* header arriving from outside, then adds its own.
  • TLS terminates here (LB tier, or the core in small mode); certificates live only here.
  • pike flood limits per source; trusted gateway sources exempt.
  • Auth-failure blocking: 10 rejects in 5 min → source dropped for 5 min.
Core node: internal network
  • X-Src-* trusted only from LB_SUBNET.
  • evapi binds to 127.0.0.1; the sidecar is its only client.
  • JSON-RPC / XML-RPC accept only localhost, the internal and RTPEngine subnets; 5071 is never public.
  • The MySQL account has rights on the kamailio schema only; spool and recordings are owned by their service accounts.
Backend holds the secrets
  • mTLS with a per-node client certificate for every sidecar.
  • Subscriber passwords stored only as HA1 = MD5(user:realm:pw); the full digest is verified in the backend.
  • Stateless nonces: timestamp + random + HMAC under a shared key ID. The backend checks age and tracks nc to stop replays.
  • Admins: bcrypt, ADMIN / VIEWER roles, audit log with before and after values.
The SIPp suites attack these boundaries directly: spoofed X-Src-* on INVITE and OPTIONS, wrong passwords until the source is blocked, AoR mismatch on REGISTER, and stale nonces.
02 kamailio ↔ sidecar / process model

No Kamailio worker ever waits on the backend

Every decision suspends the SIP transaction. The answer resumes it in an evapi worker, and the SIP worker moves on immediately.

Time budget for one request
  • Sidecar threads: one virtual thread reads evapi. Requests get their own virtual thread. Events go to a per-key serial executor (session_id, aor), so one call's events stay in Kamailio's order.
  • Never silent: a handler that throws, times out or is missing answers {"result":"ERROR"} → Kamailio replies 503.
  • Late answers are harmless: t_continue fails and is logged.
  • Re-auth and expiry timers: a 2-thread scheduler hands work to virtual threads. The event shipper never touches the evapi path.

03 message flows / caller identification

Every new INVITE starts with one call.identify

One round trip classifies the caller as a trusted gateway, a caller to challenge, or a verified subscriber.

Rewrite rules
  • The backend rewrites only the R-URI user (the dialed number).
  • Every outgoing INVITE gets To = its R-URI; the caller still sees its own To.
  • Subscriber calls present the backend's caller ID in From and PAI. Gateway calls pass through unchanged.
  • Everything after identify uses the rewritten number. IPDRs carry both numbers.
  • NOT_TRUSTED is cached per source; TRUSTED sources join trustedsrc (pike-exempt).
03 message flows / subscriber → external number

Flow 2: subscriber calls an external number

Read it like this
  • The first INVITE has no credentials, so the origin check runs; an unknown source gets 407.
  • The retry carries credentials and skips the origin check.
  • Kamailio checks locally (MySQL) that the caller is registered from the same IP, port ignored, and whether the callee is a local subscriber.
  • call.setup: GetRoutes, then Authorize, in sequence. Authorize runs only when there is somewhere to send the call.
  • Grant clock starts at 200 OK; ringing is free.
Failover: route 1 answers 503 → call.attempt, relay route 2. If all fail: one Failed IPDR listing every attempt.
03 message flows / gateway → subscriber

Flow 3: trusted gateway calls a registered subscriber

  1. INVITE without credentials → IdentifyOrigin returns TRUSTED, the gateway's account and a rewritten R-URI user (DID → subscriberId).
  2. registered("location") finds the callee → call.setup with target LOCAL. The sidecar skips GetRoutes and calls only Authorize (ORGGWTOSIP rate).
  3. On ALLOW: To = sip:<subscriberId>@domain, then lookup forks to every contact. In scaled mode each branch follows the stored Path back through the LB holding the client's connection.
  4. First 200 OK wins → call.connected → Start IPDR.

04 decisions / routing and rating

Routing and rating, from memory

Tariff and routing plans live as immutable tries on every call-control instance. Only balances and sessions touch the database. GetRoutes p99 stays under 2 ms.

Routing (off-net calls)
  1. The caller's routing plan, or the default ALL/ALL/ALL.
  2. Row with the longest prefix match on the received number, then the longest destination match. ALL ranks lowest.
  3. The row's gateways (or all active).
  4. Skip inactive, prefix-rule miss, or no buy rate.
  5. Order: priority → least cost → round-robin.
  6. Apply each gateway's prefix rewrite.

04 decisions / call time enforcement

No grace period: the call ends at T, to the second

Two clocks guard every call: the sidecar's re-authorization and Kamailio's own dialog timer. Whichever fires first ends the call.

T−10 · −6 · −3re-authorization attempts, each with a 2 s deadline; each grant adds N s
dialog timeralways set to the exact allowance end; it enforces T alone if the sidecar is gone (ALLOWANCE_EXPIRED)
final grantnever re-authorized; a late grant after T is ignored and the session is terminated
2 h ceilinghard limit after connect, whatever the grants (MAX_DURATION). A grant ≤ 10 s re-authorizes at connect

The LB tier: thin, stateful, no database, no sidecar

Signalling always passes through the LB tier in both directions. Media never does.

Lessons from Phases 41–42
  • REGISTER goes LB → core over UDP, because nathelper pings only over UDP. The core sets udp_mtu 1300 with TCP fallback, so calls on the UDP Path never fragment.
  • path_use_received on the core plus use_received on the LB deliver calls to NAT'd subscribers.
  • Egress LB goes silent → ds_mark_dst → the next call uses the other LB. LB fr_timer is 5 s.
  • A core is lost → subscribers re-register through the other core; the backend expires the lost calls.
Proven by sip/tests/scaled.sh (~17 min): Path, affinity, NAT keepalives, spoofed X-Src-*, drain, egress failover, a lost core.

07 resilience / recovery and durability

Restarts adopt live calls; money always reconciles

Sidecar restart reconciliation
  1. Reconnect evapi; wait for the first pong.
  2. dlg.list_ctx: keep confirmed dialogs with a sid variable.
  3. Rebuild each session from sessions/<id>.pb, then Reauthorize with used seconds.
  4. Granted → dialog.timeout and the normal cycle. Denied or unknown → end at the current timer.
  5. Resend every unacknowledged spooled event; then open the Control stream.

Kamailio's dialog timers protect every call throughout.

Backend: orphans and late records
Connected, silentallowance end + 60 s → charge full reservation
Never connected5 min after Authorize → release all

A late Final or Failed IPDR (say, from a spool after an outage) re-settles on the real amount as a flagged ledger adjustment, even below zero.

Sweeper and jobs claim work with FOR UPDATE SKIP LOCKED; expiry uses database time.

Drills that passed
  • kill -9 of the call-control instance holding a live call: the sidecar moved within 5 s, re-auth succeeded, and the call settled normally.
  • LISTEN connections killed at 100 cps: reconnected in ~1 s with a full reload; 4,000 calls answered at normal latency.
  • PostgreSQL restart at 50 cps: 5 of 3,000 UNAVAILABLE, the rest completed through retries.
  • POST /api/v1/call-control/reconcile → 0 mismatches after each.
